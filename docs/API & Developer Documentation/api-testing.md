# Testing APIs with Postman

This project demonstrates hands-on API testing using Postman. It focuses on manually calling API endpoints, inspecting request and response data, and writing basic JavaScript tests to validate expected behavior. The intent is to show practical familiarity with API interactions and how testing supports developers, QA analysts, and documentation accuracy.

The project uses Spotify's API and prioritizes conceptual understanding over exhaustive test coverage.

## What this project demonstrates

- Understanding of how APIs are called, requests constructed, and responses validated during testing  
- Writing lightweight JavaScript assertions to verify expected outcomes 
- Comfort working across documentation, development, and QA-adjacent workflows

## Assumptions

- The intended audience is technical, with basic familiarity with APIs and HTTP concepts.
- Testing focuses on validating expected behavior rather than uncovering edge cases or performance issues.

## Scope

Automated testing workflows (such as Newman or Postman CLI) are intentionally out of scope.
